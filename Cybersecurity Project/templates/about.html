SecureScan Technical Documentation & Guidance

A defensive web security assessment framework designed for cybersecurity students, developers, and security auditors.

What SecureScan Does

SecureScan is an automated, defensive web configuration scanner that audits web applications against modern hardening standards. Rather than conducting destructive penetration testing or sending exploit payloads, SecureScan passively inspects live HTTP response behaviors, analyzing cryptographic transport settings, browser defense headers, cross-origin resource sharing (CORS) rules, and session cookie attributes.

Primary Target Audiences:
  • Cybersecurity Students & Beginners: Learning foundational defensive concepts and OWASP secure coding standards.
  • Web Developers: Verifying that security headers and session cookies are deployed properly prior to production releases.
  • Authorized Security Labs & Audits: Conducting repeatable, non-destructive initial configuration assessments.
HTTP Security Headers Evaluated

Restricts the domains and sources from which scripts, images, and other assets can load. Mitigates Cross-Site Scripting (XSS) and data injection. SecureScan evaluates directives for dangerous keywords like 'unsafe-inline' or 'unsafe-eval'.

Instructs browsers that the site must only be accessed using HTTPS. Protects against SSL-stripping and man-in-the-middle attacks. SecureScan verifies the max-age value (minimum 6 months recommended) and checks for includeSubDomains and preload.

Disables browser MIME-type sniffing. When set to nosniff, forces user agents to adhere strictly to the declared Content-Type, mitigating MIME confusion exploits.

Prevents Clickjacking attacks by controlling whether a page can be rendered inside a <frame>, <iframe>, or <object>. SecureScan also checks if a modern CSP frame-ancestors directive provides equivalent or superior protection.

Governs how much referrer information (URL paths, sensitive query parameters) is included with requests when navigating from the application to external links.

Allows web developers to restrict or disable powerful browser hardware APIs (e.g. camera, microphone, geolocation, screen-wake-lock) across first-party code and embedded third-party iframes.
Assessment Limitations & Scope Boundaries

To maintain safe, non-destructive operation, SecureScan intentionally DOES NOT perform:

  • Dynamic injection testing (SQL injection, Command injection, Path traversal).
  • Active exploitation, brute-force credential stuffing, or password guessing.
  • Authenticated business logic flaw analysis.
  • Arbitrary JavaScript execution or headless browser crawling.
  • Internal port scanning or network reconnaissance.
Important Note: The absence of findings from a passive configuration scan does not guarantee that the target is free from web application vulnerabilities.
Severity Classification
HIGH SEVERITY

Direct exposure of sensitive data, plaintext HTTP transmission, invalid TLS certificates, or dangerous CORS configurations (wildcard origin + credentials).

MEDIUM SEVERITY

Missing vital defense-in-depth controls such as Content-Security-Policy or X-Frame-Options (Clickjacking vulnerability), and missing HttpOnly flags on session cookies.

LOW SEVERITY

Missing X-Content-Type-Options, sub-optimal HSTS duration, or missing explicit SameSite cookie directives.

INFORMATIONAL

Verified best practices, properly configured headers, or non-applicable rules for the detected scheme.

Posture Score Formula

The security score is calculated starting from a baseline of 100 with weighted deductions:

Score = 100 - (High * 25 + Med * 10 + Low * 4)
  • A 90 – 100: Hardened Posture
  • B 75 – 89: Good (Minor hardening)
  • C 60 – 74: Fair (Review needed)
  • D 40 – 59: Poor (Multiple risks)
  • F 0 – 39: Critical Deficits
